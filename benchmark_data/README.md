# LMAI Inspector Accuracy Benchmark & Ground-Truth Dataset Guide

This directory contains benchmark datasets, image directories, and ground-truth specifications for evaluating the accuracy and compliance performance of the **LMAI Inspector** packaging analysis pipeline.

---

## 1. Ground-Truth Authoring Principles

> [!IMPORTANT]
> **CRITICAL RULE**: Benchmark ground truth **MUST NOT** be generated by Gemini or any other LLM.
> Ground truth represents the objective, manually-verified reality of the physical package. Using AI to judge AI defeats the purpose of an objective engineering benchmark.

### Step-by-Step Guide for Adding a Real Package

1. **Capture Package Panels**:
   - Capture clear, well-lit photos of all informative sides of the commodity (Front, Back, Side panels, Top/Bottom flap).
   - Save the images into a subfolder: `benchmark_data/packages/<CASE_ID>/` (e.g. `benchmark_data/packages/PKG005/front.jpg`).
   - Note: Real photos under `packages/` are ignored by `.gitignore` to prevent committing sensitive or unapproved photos.

2. **Manually Inspect the Package**:
   - Read every printed declaration directly from the package with human eyes.
   - Record exact printed text, units, punctuation, and currency symbols.

3. **Enter Verified Declarations**:
   - Populate `expected_declarations` in `dataset.json` using the canonical field names (see list below).
   - If a declaration is missing from the package, omit it or set `"value": null`.
   - Set `"required": true` for declarations legally mandated for this package type.

4. **Enter Expected Regulatory Context**:
   - `category`: `FOOD`, `COSMETIC`, `HOUSEHOLD`, `PHARMACEUTICAL`, `ELECTRONICS`, etc.
   - `package_type`: `RETAIL` or `WHOLESALE`.
   - `import_status`: `DOMESTIC` or `IMPORTED`.

5. **Enter Verified Rule Statuses**:
   - Map expected statutory rules (`PASS`, `FAIL`, `NOT_VERIFIABLE`, `NOT_APPLICABLE`).
   - Verify against the official Legal Metrology (Packaged Commodities) Rules, 2011 and FSSAI/Cosmetics regulations.
   - For image-unverifiable physical tests (e.g. actual net content physical weighing, caliper measurements), set status to `NOT_VERIFIABLE`.

6. **Add Difficulty Tags**:
   - Label package conditions to allow slice-and-dice evaluation.

## 2. Canonical Declaration Fields

Use only canonical field names recognized by the pipeline:

| Canonical Field Name | Description | Example Format |
| :--- | :--- | :--- |
| `PRODUCT_NAME` | Commercial product title | `NutriOats Digestive Cookies` |
| `BRAND` | Commercial brand/trademark | `NutriOats` |
| `GENERIC_NAME` | Common or generic name of commodity | `Biscuits` |
| `DECLARED_NET_QUANTITY` | Net weight, volume, or count | `500 g`, `100 ml`, `10 N` |
| `MRP` | Maximum retail price inclusive of taxes | `₹50.00`, `Rs. 45.00` |
| `MANUFACTURER_NAME` | Name of manufacturing entity | `ABC Foods Private Limited` |
| `MANUFACTURER_ADDRESS` | Factory or registered address | `Plot 42, Sector 5, Pune 411018` |
| `PACKER_NAME` | Third-party packing entity (if applicable) | `XYZ Packaging Co` |
| `PACKER_ADDRESS` | Address of packing entity | `Industrial Area, Phase 1, Delhi` |
| `MARKETER_NAME` | Marketing/distributor entity | `Global Consumer Products Ltd` |
| `MARKETER_ADDRESS` | Address of marketer | `Nariman Point, Mumbai 400021` |
| `IMPORTER_NAME_ADDRESS`| Importer name and address | `Imported by ABC Ltd, Mumbai` |
| `COUNTRY_OF_ORIGIN` | Country of manufacture | `India`, `Made in USA` |
| `MONTH_YEAR_MANUFACTURE`| Manufacturing date or month/year | `04/2024`, `15/04/2024` |
| `PACKING_DATE` | Packaging date (if distinct) | `05/2024` |
| `EXPIRY_DATE` | Expiration date | `12/2025` |
| `BEST_BEFORE_USE_BY` | Best before duration or date | `6 months from manufacture` |
| `BATCH_NUMBER` | Batch, lot, or code number | `NB-402`, `Lot 12` |
| `CONSUMER_CARE` | Helpline telephone, email, address | `care@example.in, 1800-111-222` |
| `FSSAI_LICENSE` | 14-digit FSSAI license (food) | `10014011005544` |
| `VEG_NONVEG_SYMBOL` | Food green/brown dot symbol | `VEGETARIAN` or `NON_VEGETARIAN` |
| `INGREDIENTS_LIST` | Full ingredient list | `Wheat flour, sugar, butter` |
| `NUTRITIONAL_INFO` | Nutrition information panel | `Per 100g: Energy 450 kcal` |

## 3. Supported Difficulty Tags

Tag benchmark cases to test pipeline resilience under varying real-world conditions:

- **Environmental**: `clean`, `blurry`, `low_light`, `glare`, `shadow`
- **Geometric**: `curved`, `cropped`, `rotated`, `small_text`
- **Panel Layout**: `single_panel`, `multi_panel`, `multipack`, `barcode`, `no_barcode`
- **Complexity**: `multiple_prices`, `multiple_dates`, `manufacturer_marketer`, `manufacturer_packer`, `partial_evidence`, `ocr_noise`
- **Regulatory Scope**: `food`, `cosmetic`, `household`, `electronics`, `retail`, `wholesale`, `domestic`, `imported`
- **Compliance Outcome**: `compliant`, `non_compliant`, `review_required`

## 4. Running the Benchmark

### Offline / Reproducible Mode (MODE A - Default)
Consumes **ZERO** live Gemini API quota. Uses deterministic extractors and pre-recorded synthetic/mock responses:
```bash
python -m backend.benchmark.run_benchmark --dataset benchmark_data/dataset.example.json --output benchmark_output/
```

### Filtering by Tag or Case
```bash
# Evaluate only blurry packages
python -m backend.benchmark.run_benchmark --tag blurry --output benchmark_output/

# Evaluate only a specific case ID
python -m backend.benchmark.run_benchmark --case PKG001 --output benchmark_output/
```

### Live Gemini Benchmark Mode (MODE B)
Explicitly tests Gemini resolution with live remote inference:
```bash
# Requires valid GEMINI_API_KEY in environment or .env
python -m backend.benchmark.run_benchmark --live --dataset benchmark_data/dataset.example.json --output benchmark_output/
```
Or via environment flag:
```bash
set RUN_GEMINI_BENCHMARK=1
python -m backend.benchmark.run_benchmark --dataset benchmark_data/dataset.example.json
```
